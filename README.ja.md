# FastGif

[English](README.md) | **日本語**

Windows 11 用の小さくて速いアニメーション GIF ビューワです。**1 枚目をできるだけ早く画面に出し**、そのあとアニメーションを再生することを一番の目標にしています。

![FastGif のスクリーンショット](docs/screenshot.png)

- C++ と Win32 API だけで書いています。C ランタイム（CRT）も使っていません
- **単体の exe（約 46KB。うちアイコンが約 16KB）で動き、追加の DLL は不要です**
- 使う DLL は Windows に最初から入っているもの（kernel32 / user32 / gdi32 / dwmapi）だけです
- GIF のデコーダは自作で、WIC は使っていません

## 特長

- 起動が速い。手元の GIF では 1 枚目のデコードが約 0.2〜1.9ms でした（WIC だと 0.45〜9.1ms）
- 高精度タイマーで、なめらかかつ正確に再生します
- 大きくて速い GIF（たとえば 1920×1080・100fps）でも速度を保ちます。再生が遅れ始めたら、裏のスレッドでフレームを展開し、ウィンドウサイズに縮小した状態でメモリに貯める方式に切り替えます
- ウィンドウより大きい画像は縦横比を保って縮小し、小さい画像は等倍のまま中央に表示します
- マウスホイールで同じフォルダの前後の GIF を開けます。名前順で、数字は数値として並べ、端まで行くと反対側に戻ります
- ウィンドウの位置・サイズ・最大化状態を覚えています
- ドラッグ&ドロップ、ファイルを開くダイアログ、コマンドライン引数で開けるので、関連付けにも使えます
- フルスクリーン、コマ送り、透過部分の背景の切り替えができます

## 使い方

```
fastgif.exe <ファイル.gif>
```

exe やウィンドウに GIF をドロップするか、Ctrl+O でも開けます。

エクスプローラーから FastGif で開くようにするには、GIF を右クリック →「プログラムから開く」→「別のプログラムを選択」で `fastgif.exe` を選び、「常に使う」を選んでください。

### 操作

| キー / マウス | 機能 |
|---|---|
| Space | 再生 / 一時停止 |
| ← / → | 前 / 次のフレーム（一時停止します） |
| Home | 最初のフレームへ |
| マウスホイール | 上: 前の GIF / 下: 次の GIF（同じフォルダ） |
| PageUp / PageDown, ↑ / ↓ | 前 / 次の GIF |
| F / F11 / Enter / ダブルクリック | フルスクリーンの切り替え |
| B | 透過部分の背景を切り替え（市松 / 暗い灰色 / 白 / 黒） |
| Ctrl+O | ファイルを開く |
| F1 / 右クリック | 操作説明 |
| Esc | フルスクリーンを解除、または終了 |

### ウィンドウの設定（fastgif.ini）

- ウィンドウを閉じるときに、位置・サイズ・最大化状態を `fastgif.ini` に保存します。次に起動すると同じ位置・サイズで開きます
- 保存先は exe と同じフォルダです。**そのフォルダに書き込めない場合に限り**（`Program Files` など）、`%APPDATA%\FastGif\fastgif.ini` に保存します。読み込むときも同じ順番です
- 保存した位置のモニタが外れている場合は、サイズだけ引き継ぎ、マウスのあるモニタの中央に開きます

## 1 枚目を早く出すための工夫

- ファイルをメモリマップで開き、起動時はヘッダと 1 枚目の位置だけを解析します。残りのフレームは再生に合わせて順に解析します
- 1 枚目のデコードを別スレッドで行い、その間にメインスレッドでウィンドウを作ります
- ウィンドウが開くときの DWM のアニメーションを止めて、すぐに表示します
- フォルダの走査は起動時には行いません。最初にホイールや PageUp/PageDown で別のファイルに移動したときに 1 回だけ行います
- shell32（ドラッグ&ドロップ）と comdlg32（ファイルを開くダイアログ）は、初めて使うときに読み込みます
- LZW デコーダは、辞書の各項目を「出力済みデータ上の位置と長さ」で持ち、そこから文字列を直接コピーします
- フレームを表示したらすぐ次のフレームを先にデコードしておきます。切り替えは高精度の Waitable Timer で絶対時刻に合わせて行うので、時間のズレが積み重なりません
- 縮小は自作の面積平均（SSE4.1、CPU コアに分けて並列処理）で行います。見た目は GDI の HALFTONE と同等で、約 16 倍速くなります

## 大きな GIF の再生

1 枚目を最速で出すため、最初は UI スレッドでフレームを展開します。フレームごとに「表示時間内に処理が終わったか」を記録し、直近 8 フレーム中 6 フレームが遅れたら、次の方式に切り替えます。

- ファイルの残りをまとめて先読みします（`PrefetchVirtualMemory`）。遅いドライブでも、細切れの読み込みで展開が止まらないようにするためです
- 裏のスレッドがフレームを展開し、背景と合成してウィンドウサイズに縮小し、メモリに貯めます。2 周目以降はメモリから再生します
- メモリの上限は、空いている物理メモリの半分（最大 3GB）です。入りきらない場合は、再生位置から遠いフレームから捨てます
- ウィンドウサイズや背景を変えると、新しい条件でフレームを作り直します。作り直すまでの間は、今あるフレームを引き伸ばして表示します

最初の数フレームの遅れは問題にしないので、1 枚目は今までどおりすぐに表示されます。

## ビルド

Visual Studio 2022 の「C++ によるデスクトップ開発」が必要です。

```
build.bat
```

exe は `publish\fastgif.exe` に、中間ファイルは `build\` に出力されます。

| スクリプト | 用途 |
|---|---|
| `test\build_test.bat` | `test_wic.exe`（自作デコーダの全フレームを WIC と比較）と `bench.exe`（展開・縮小の 1 フレームあたりの時間を計測）をビルドします |
| `tools\make_icon.ps1` | アイコン（`res\fastgif.ico`）を作り直します |
| `tools\make_sample_gif.ps1` | サンプルアニメーション（`docs\sample.gif`）を作り直します |

## 仕様メモ

- 遅延が 0（指定なし）のフレームは 100ms 表示します。それ以外は、1/100 秒（10ms）も含めて指定どおりに表示します
- ファイルに書かれたループ回数は無視し、常にループ再生します
- disposal 2（背景で消去）は、ブラウザと同じく透明で消去します
- 扱える画像サイズは 6,400 万ピクセル（約 8192×8192）までです
